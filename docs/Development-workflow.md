# Development Workflow

The project will follow a **Scrumban** approach, combining sprint planning with a continuous Kanban-style workflow.

## 1. Sprint planning

At the beginning of each sprint:

- Define a clear sprint goal.
- Select the most relevant backlog items for that goal.
- Add the selected tasks to the GitHub Project board.

## 2. Task flow

Tasks will move through the following states:

**Todo → In Progress → Done**

Only a limited number of tasks should be in progress at the same time.

## 3. Implementation

When development work begins:

- Move the related Issue to **In Progress**.
- Create a separate branch when needed.
- Implement the required functionality.
- Add or update tests when appropriate.
- Commit changes using clear and descriptive messages.
- Review the changes before merging them into the main branch.

## 4. Task completion

A task is considered complete when:

- The required work has been implemented.
- The result has been tested or reviewed.
- The changes have been integrated into the main branch.
- The related Issue has been moved to **Done** and closed.

## 5. Sprint review

At the end of each sprint:

- Review the completed work.
- Identify unfinished tasks.
- Update the backlog if necessary.
- Record problems or improvements for the next sprint.
