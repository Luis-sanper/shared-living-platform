# Assumtions

## Users and roles

- Each user will have their own account, identified by their name and role.
- Each user has only one role.
- People who live in a shared house are referred to as tenants in the system.
- Landlords will have access only to specific sections of the platform related to their role.
- Each user must be authenticated to access private flat information.
- The first version will use a simple permission system based on user roles.

## Flats and access

- Each flat will have a private space for its tenants and, when applicable, its landlord.
- Each flat will contain one or more rooms.
- Each room can be assigned to only one tenan at a time in the first version.
- Each user will have access to only one flat in the first version of the system.
- Each landlord will have access to only one flat in the first version.
- Only landlords can create flats and define rooms in the first version.
- Tenants join a flat through an invitation to an specific available room.
- Users can leave a flat or be removed from it. Accepting a new invitation will move them to another flat after confirmation.

## Platform and technical assumptions

- An internet connection will be required to use the application.
- The platform will store uploaded images.
- The first version will be web-based, with the possibility of developing a dedicated mobile application in the future.
- The first version of the application will be developed in English.
- The first version assumes a relatively small number of users and flats, so scalability is not a primary concern.

## Social space

- Social activities will be visible to all users, with filters by city and country.

## Usability

- The application will be designed to be simple and accessible to a broad range of users.
